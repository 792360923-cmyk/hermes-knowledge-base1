# 防偷懒验证器开发中反复"写完就报完成"——8个bug靠用户逼自查才挖出

## 错误表现（元问题：写完就报完成，不自测）

2026-08-25 开发防偷懒自动验证器（anti_slacker.py）时，每写一版就向威猛先生报"完成"，但实际代码有 bug。威猛先生当天反复追问：

1. "你有没有偷懒的去做这个事情"
2. "再次验证"
3. "再次严格检查一遍"
4. "再次验证"
5. "再次严格的测试一遍"

**每次被逼自查，都挖出新 bug，累计 10 个：**

| # | Bug | 根因 |
|---|-----|------|
| 1 | VT-* 规则ID被误判为笼统词 | 规则ID里含"USB"字样，`check_vague_terms` 把自己规则ID当成了笼统词 |
| 2 | "未标注"被误判为笼统 | 合规写法"电池未标注"被当成偷懒，缺排除词 |
| 3 | USB-C 变体未识别 | "USB-C接口"未匹配 Type-C 模式，缺变体 |
| 4 | Python正则 `\b` 中文混排失效 | 中文是 `\w`，`\b` 不匹配中英文边界，需 `(?<![a-zA-Z0-9])` lookbehind |
| 5 | 亚马逊来源歧义 | "亚马逊"同时在 SOURCE_MARKERS 和 VAGUE_SOURCES，逻辑冲突 |
| 6 | CSV空单元格None崩溃 | `row.get()` 返回 None 未转 str，`.strip()` 报 AttributeError |
| 7 | "分析"关键词宽泛误判结论段 | "数据分析显示"被当成结论段，导致合规报告被 ST-CONC-SHORT 误杀 |
| 8 | TBL-ERR 缺失标题映射 | CSV读取失败的 rule_id 不在 TITLE_MAP，生成案例标题缺失 |
| 9 | location 含反引号 markdown 注入 | 违规位置文本含反引号，写入知识卡片时破坏 markdown 格式 |
| 10 | 标题行含数字误判无来源 | "【第2页】"里的"2"被当成业务数据，触发 SRC-MISSING |

## 错误原因（根本原因：交付前没跑测试）

1. **写完 = 默认没问题**：每次写完代码就报"完成"，心理默认"应该能跑"，没实际执行。
2. **没跑回归测试**：`test_anti_slacker.py`（56项回归）是第5轮才补的，前4轮根本没有测试。
3. **没测边界条件**：中文混排、空值None、markdown特殊字符、标题行、规则ID自触发——这些边界一个都没提前想。
4. **没测英文场景**：英文句号分句、英文来源混合等场景没覆盖。
5. **"报完成"快于"验证完"**：倾向于给结论，而不是给"经过验证的结论"。

## 正确做法

1. **写完 ≠ 做完，测试通过才算做完**：任何代码/脚本/工具，写完必须先跑一遍，看真实输出。
2. **先写回归测试，再改代码**：把 `test_anti_slacker.py`（56项）作为交付门禁，`python3 test_anti_slacker.py` 退出码≠0 就禁止报完成。
3. **边界条件清单**（每次交付前过一遍）：
   - 中文/英文混排（`\b` 陷阱、分句符）
   - 空值/None/空字符串/空CSV
   - 特殊字符（反引号/管道/星号/markdown注入）
   - 标题行/章节行/编号行
   - 规则ID自触发（代码里的词会不会命中自己的规则）
   - 大小写变体（USB-C/TYPE-C/type-c）
4. **修一个 bug 必须回归**：改完代码立刻跑全量测试，确认没引入新问题。
5. **主动自查，不要等用户逼**：交付前自己先跑测试、先测边界，把"用户逼我自查"变成"我主动自查"。

## 后果

- 当天用户反复追问5次，消耗大量来回
- 8个bug本可以在第一版就发现，拖到第7轮才修完
- 前几版的"完成"是虚假的完成，浪费了用户的信任

## 适用场景

所有需要写代码/脚本/工具/表格的任务。核心是"交付前必须验证"这条元原则。

## 教训

**防偷懒工具的开发过程，暴露了"我"自己也会偷懒——不测试就交付。** 最深的教训不是8个bug本身，而是：

> "写完就报完成"是最隐蔽的偷懒。它不体现在输出内容里，体现在"没验证就下结论"这个动作里。

工具（验证器）能拦住内容的偷懒，但拦不住"不跑工具"的偷懒。所以唯一的解法是把"测试通过"变成交付的硬门禁，而不是靠自觉。

## 附：通用技术教训（跨项目可复用）

| 技术点 | 教训 |
|--------|------|
| Python正则 `\b` | 中文是 `\w`，`\b` 在中英文边界失效，用 `(?<![a-zA-Z0-9])...(?![a-zA-Z0-9])` |
| CSV DictReader | 空单元格返回 `None`，必须 `(row.get(k) or '')` 转空串 |
| markdown生成 | 用户输入写进 .md 前，清洗反引号/管道/星号，防注入 |
| 规则自触发 | 规则引擎的规则ID/枚举值可能命中自己的匹配词，需加排除词 |
| 标题行过滤 | 文本扫描要跳过 `【】`/`#`/编号短行，否则"第2页"里的数字误判 |
