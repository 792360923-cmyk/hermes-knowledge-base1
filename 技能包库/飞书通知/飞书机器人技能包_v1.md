# Feishu (Lark) Self-Built App Bot

Create and run a Feishu/Lark self-built app bot using WebSocket long connection.

## Setup (done once by user)

1. Feishu Developer Console → Create custom app → "Enterprise self-built"
2. Add bot capability, open `im:message` and `im:message:send_as_bot` permissions
3. Events & Callbacks → Long Connection mode → Add `im.message.receive_v1` event
4. Version Management → Create Version → Publish (WebSocket won't work until published!)
5. Copy App ID and App Secret from Credentials

## Python code (proven working)

```python
#!/usr/bin/env python3
import json, requests, lark_oapi as lark
from lark_oapi.event.dispatcher_handler import EventDispatcherHandlerBuilder
from lark_oapi.api.im.v1 import P2ImMessageReceiveV1

APP_ID = "..."
APP_SECRET = "..."

def get_token():
    r = requests.post('https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal',
        json={"app_id": APP_ID, "app_secret": APP_SECRET}, timeout=10)
    return r.json()["tenant_access_token"]

def reply_msg(msg_id, text):
    """REST API reply — more reliable than SDK im.v1.message.reply"""
    token = get_token()
    content = json.dumps({"text": text})
    r = requests.post(
        f"https://open.feishu.cn/open-apis/im/v1/messages/{msg_id}/reply",
        headers={"Authorization": f"Bearer {token}", "Content-Type": "application/json"},
        json={"content": content, "msg_type": "text"}, timeout=10)
    return r.json().get("code") == 0

class FeishuBot:
    def __init__(self):
        handler = (EventDispatcherHandlerBuilder("", "")
            .register_p2_im_message_receive_v1(self.on_message)
            .build())
        self.ws = lark.ws.Client(app_id=APP_ID, app_secret=APP_SECRET,
            event_handler=handler, log_level=lark.LogLevel.INFO, auto_reconnect=True)

    def on_message(self, event: P2ImMessageReceiveV1):
        msg = event.event.message
        try: text = json.loads(msg.content).get("text", "")
        except: text = msg.content
        text = text.replace("@_user_1", "").strip()
        if text:
            print(f"[lark] {text[:200]}")
            reply_msg(msg.message_id, f"got: {text[:80]}")

    def start(self): self.ws.start()

if __name__ == "__main__":
    FeishuBot().start()
```

## Key pitfalls

1. **Never hardcode WebSocket URL.** The SDK auto-discovers it. All manual guesses return 404.
2. **App MUST be published** before WebSocket connects. Before publishing: 404 or INVALID_SERVICEID.
3. **Reply via REST API only.** SDK `client.im.message.reply()` and `client.im.v1.message.reply()` both fail with import/attribute errors. Use direct REST POST to `/open-apis/im/v1/messages/{msg_id}/reply`.
4. **EventDispatcherHandlerBuilder params** MUST be empty strings `""` for long connection mode.
5. **OCR from screenshots** can misread secrets. If `code: 10014`, ask user to copy-paste directly.
6. **token `code: 0` means success**, not failure. Check `data.get("code") == 0`.
7. **Permissions need re-publish.** After granting new permissions in the developer console, create and publish a new version before they activate.
8. **Bitable list API returns 404.** The direct REST endpoint `/open-apis/bitable/v1/apps` is not accessible. Use Drive API to find files, or use SDK `client.bitable.v1.app.get(app_token)` with a known app_token from the table URL.

## Bitable (多维表格) & Sheets access

For table read/write, the user must first share the table with the bot. Then:

```python
import lark_oapi as lark
client = lark.Client.builder().app_id(APP_ID).app_secret(APP_SECRET).build()

# List bitable files the bot can see (via Drive API)
TOKEN = get_token()  # use REST get_token helper
r = requests.get('https://open.feishu.cn/open-apis/drive/v1/files',
    headers={'Authorization': f'Bearer {TOKEN}'},
    params={'page_size': 20}, timeout=10)

# With a known app_token, read table records
resp = client.bitable.v1.app_table_record.list(
    lark.bitable.v1.ListAppTableRecordRequest.builder()
    .app_token("YOUR_APP_TOKEN")
    .table_id("YOUR_TABLE_ID")
    .page_size(100)
    .build()
)
```

Bitable SDK methods live under `client.bitable.v1`:
- `.app` — create/copy/get/update app
- `.app_table` — manage tables within a base
- `.app_table_record` — CRUD on record rows
- `.app_table_field` — field definitions
