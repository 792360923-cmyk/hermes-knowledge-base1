# 飞书自建应用机器人 — WebSocket 长连接配置

## 触发条件

当用户需要配置飞书机器人、连接飞书消息、或使用飞书 SDK 时加载。

---

## 前置条件

1. 飞书开发者后台有自建应用（企业自建应用，非商店应用）
2. 已获取 App ID 和 App Secret

---

## 配置步骤

### 一、飞书开发者后台配置

**1. 添加机器人能力**
- 进入应用 → 添加应用能力 → 选「机器人」

**2. 权限管理**
- 搜索并开通：`im:message`（获取消息）、`im:message:send_as_bot`（发送消息）
- 如果需要群聊，加 `im:chat` 相关权限

**3. 事件订阅（关键步骤）**
- 进入「事件与回调」→ 事件配置
- 订阅方式选 **「使用长连接接收事件」**（推荐）
- 点「添加事件」→ 搜索并勾选 `im.message.receive_v1`（接收消息 v2.0）
- 点「保存」

**4. 发布应用（必做！不发布长连接不通）**
- 左边点「版本管理与发布」→「创建版本」
- 填版本号（如 1.0.0）和说明 → 保存 → 申请发布
- 未发布前 WebSocket 会返回 404

**5. 验证连接**
- 回到「事件与回调」→ 点「重新验证」
- 等服务端客户端启动后自动连通

### 三、生产环境架构：飞书 → Hermes 消息队列

以下架构适用于需要 AI 智能回复的场景（而非固定模板）：

```python
#!/usr/bin/env python3
"""飞书 → Hermes 桥接机器人
飞书消息 → inbox → cronjob(AI处理) → outbox → REST API回复
"""

import json, requests, os, time, subprocess, lark_oapi as lark
from lark_oapi.event.dispatcher_handler import EventDispatcherHandlerBuilder
from lark_oapi.api.im.v1 import P2ImMessageReceiveV1

APP_ID = "cli_xxxxxxxx"
APP_SECRET = "xxxxxxxx"
INBOX = "/tmp/feishu_inbox"
OUTBOX = "/tmp/feishu_outbox"

os.makedirs(INBOX, exist_ok=True); os.makedirs(OUTBOX, exist_ok=True)

def get_token():
    r = requests.post('https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal',
        json={"app_id": APP_ID, "app_secret": APP_SECRET}, timeout=10)
    return r.json()["tenant_access_token"]

def reply_msg(msg_id, text):
    token = get_token()
    content = json.dumps({"text": text})
    requests.post(
        f"https://open.feishu.cn/open-apis/im/v1/messages/{msg_id}/reply",
        headers={"Authorization": f"Bearer {token}", "Content-Type": "application/json"},
        json={"content": content, "msg_type": "text"}, timeout=10)

def process_message(msg_id, text, chat_id, sender):
    inbox_file = os.path.join(INBOX, f"{msg_id}.json")
    outbox_file = os.path.join(OUTBOX, f"{msg_id}.txt")
    with open(inbox_file, "w") as f:
        json.dump({"msg_id": msg_id, "chat_id": chat_id, "sender": sender, "text": text, "time": time.time()}, f, ensure_ascii=False)
    # 立即回复"处理中"，然后等 cronjob 处理
    reply_msg(msg_id, "处理中...")
    for _ in range(22):
        time.sleep(3)
        if os.path.exists(outbox_file):
            with open(outbox_file) as f:
                reply = f.read().strip()
            if reply:
                reply_msg(msg_id, reply)
            os.remove(outbox_file); os.remove(inbox_file)
            return

class FeishuBot:
    def __init__(self):
        event_handler = (
            EventDispatcherHandlerBuilder("", "")
            .register_p2_im_message_receive_v1(self.on_message)
            .build()
        )
        self.ws = lark.ws.Client(
            app_id=APP_ID, app_secret=APP_SECRET,
            event_handler=event_handler,
            log_level=lark.LogLevel.INFO, auto_reconnect=True
        )
    def on_message(self, event: P2ImMessageReceiveV1):
        msg = event.event.message
        text = json.loads(msg.content).get("text", "").replace("@_user_1", "").strip()
        if text:
            process_message(msg.message_id, text, msg.chat_id,
                event.event.sender.sender_id.open_id if event.event.sender else "?")
    def start(self):
        print("飞书→Hermes桥接已启动"); self.ws.start()

if __name__ == "__main__":
    FeishuBot().start()
```

**配合 cronjob（每分钟）**：
```
hermes cronjob create --schedule "*/1 * * * *" --prompt "处理/tmp/feishu_inbox/中的JSON消息：读取text生成智能中文回复写入/tmp/feishu_outbox/{msg_id}.txt，处理完删inbox文件。无消息则结束。"
```

**注意**：不要直接用子脚本（如 `feishu_reply.py`）做自动回复——那只是固定模板匹配，不是 AI。必须走 cronjob 触发 Hermes 主引擎处理才能做复杂任务。

## 常见坑

| 问题 | 原因 | 解决 |
|------|------|------|
| WebSocket 握手 404 | 应用未发布 | 版本管理与发布→创建版本→发布 |
| WebSocket 握手 400 `INVALID_SERVICEID` | URL 写错了 | 不要硬编码 URL，SDK 自动发现 |
| App Secret 校验失败 `code: 10014` | **截图OCR字符变形**（`FUtN`≠`FUitN`） | **点复制按钮获取，不要从截图手抄** |
| 收不到消息 | 没订阅 `im.message.receive_v1` | 事件与回调→添加事件→勾选 |
| `EventDispatcherHandler` 参数报错 | 非空字符串 | 必须传 `("", "")` |
| SDK回复报错 `no attribute 'message'` | ImService没有message属性 | 用 `client.im.v1.message.reply()` 而非 `client.im.message.reply()` |
| 多维表格写入 403 Forbidden | 机器人只有阅读权限 | 表格右上角分享→找机器人→改成"可编辑" |
| 多维表格列表 404 | 多维表格无列表API | 通过 `drive/v1/metas/batch_query?doc_type=wiki` 从Wiki链接获取真实 `app_token` |
| 飞书只能模板回复 | 接了本地脚本而非AI引擎 | 必须走 inbox→cronjob→Hermes→outbox 架构 |

## 补充：测试消息发送（不需要长连接）

```python
import requests, json

r = requests.post('https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal',
    json={'app_id': APP_ID, 'app_secret': APP_SECRET})
token = r.json()['tenant_access_token']

# 查机器人所在的群
r2 = requests.get('https://open.feishu.cn/open-apis/im/v1/chats',
    headers={'Authorization': f'Bearer {token}'})
print(r2.json())  # 获取 chat_id

# 发消息到群
requests.post('https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=chat_id',
    headers={'Authorization': f'Bearer {token}', 'Content-Type': 'application/json'},
    json={
        'receive_id': 'oc_xxxxxxxx',
        'msg_type': 'text',
        'content': json.dumps({'text': '测试消息'})
    })
```

## 补充：多维表格（Bitable）集成

详见 `references/feishu-bitable.md` — 包含权限配置、获取app_token、字段类型、读写API、常见坑。关键要点：
- 多维表格没有列表API，需通过 `drive/v1/metas/batch_query` 从Wiki链接获取真实token
- 写入需"可编辑"权限（不只是"可阅读"）
- 写入用字段名而非字段ID
