# 物流追踪技能包（FBA 头程物流追踪）

用 **17TRACK 官方 API**（空运/快递）+ **货代周报表**（海运卡派）双数据源批量追踪 FBA 头程货件（中国→美国/英国/德国），每天自动生成汇总表，推送到 Discord 指定频道并 @ 指定用户。

## 触发条件

- 用户要求"查物流 / 追踪头程 / 更新物流状态 / 物流日报 / 物流周报"
- 用户发来新的追踪表 xlsx 或货代周报表 xlsx

## 双数据源逻辑（核心）

| 货件类型 | 数据源 | 说明 |
|---|---|---|
| 空运 / 快递 / 海派快递派（UPS/FedEx/DPD 单号） | 17TRACK API | 能查到签收/清关/运输中 |
| 海运卡派（云驼/信易通 单号） | 货代周报表 | 卡派单号 17TRACK 查不到，但货代表有船名/ETD/ETA/状态 |

匹配键：货代表的「运单号」= 追踪表的「追踪单号」。

## 空运/海运判定（从"货代/渠道"列）

- 含「卡派」→ **海运**（到港结束，后续卡车派送查不到定位）
- 含「快递/特快/空派/空运/海派」→ **空运**（跟踪到亚马逊签收）
  - ⚠️「美森正班-快递派」「海派」虽带"美森/海"字，但走 UPS/FedEx 尾程能查签收，归**空运**
- 含「海运/美森」→ **海运**
- ⚠️ 陷阱：「递延」是英国 VAT 税务递延，**不是**运输方式，不能当空运关键词

## 17TRACK 状态映射（sub_status → 中文）

| sub_status | 中文 |
|---|---|
| Delivered_* | 已签收 |
| OutForDelivery_* | 派送中 |
| InTransit_CustomsProcessing | 清关中 |
| InTransit_PickedUp | 已揽收 |
| InTransit_* | 运输中 |
| InfoReceived | 已获取信息 |
| Exception_* / Alert | 异常 / 异常提醒 |
| Expired | 超时未更新 |
| NotFound | 查不到 |

## 货代状态映射（货代表"最新轨迹状态" → 统一状态）

| 货代状态 | 统一状态 |
|---|---|
| 已开船 | 海运中 |
| 计划交仓 | 计划交仓 |
| 货物已签收 | 已签收 |
| 已转火车 | 已转火车 |
| 已卸船 | 已卸船 |
| 到港延误/查验中/退运/扣关/丢件/破损 | 异常 |

## 关键节点识别（基于 17TRACK description 关键词，优先级从高到低）

- 已签收 ← `delivered`
- 派送中 ← `out for delivery`
- 清关完成 ← `released by government agency` / `cleared customs`
- 清关中 ← `clearing agency` / `awaiting final release` / `customs`
- 入境/到港 ← `import scan`
- 到港 ← `arrived at port` / `port of discharge` / `vessel`
- 已出运 ← `departed` / `export scan`
- 到达中转 ← `arrived at facility`
- 已揽收 ← `we have your package`
- 已获取信息 ← `label created`
- 异常 ← `exception`

## 三种"查不到"必须区分（重要）

1. **Carrier cannot be detected** → 货代内部单号，真查不到（云驼卡派 `999...`、清速达纯数字、信易通卡派 `XYT...`）
2. **No tracking information at this time** → 承运商已识别但暂无轨迹（海运头程 UPS/FedEx 单号要等货到美国才激活，或刚发货未录入）→ 标"待更新"
3. **NotFound 但 carrier 已识别** → 单号已生成但货未发/未激活 → 标"待更新"

## 17TRACK API 认证

- 端点：`https://api.17track.net/track/v2.2`
- 认证 header：`17token: <API_KEY>`
- 关键端点：
  - `POST /register`（批量 ≤40，`auto_detection=1`）
  - `POST /gettrackinfo`（批量 ≤40，**不传 carrier** 自动识别已注册单号）
- **API Key 存于本地 /root/tracking/tracking.py 的 API_KEY 变量，不入库。** 获取方式：17TRACK 官网 api.17track.net 注册"API 账户"（免费试用，无需信用卡）
- ⚠️ 网页版 `17track.net` 被 Cloudflare 反爬拦截，**必须走 API**（API 端点不受拦截）

## 货代周报表解析（云驼格式，23 列）

关键列名：运单号 / FBA号码 / ETD(开船) / ETA(到港) / 航名(船名) / 航次 / 最新轨迹状态 / 最新轨迹 / 签收链接 / 轨迹日期

- 匹配键：货代表的「运单号」= 追踪表的「追踪单号」
- 其他小货代（信易通卡派等）无表格信息 → 标记"查不到"

## 追踪表解析（分区块结构）

- 分区块：每个区块第一行是批次标题（含店铺名），接着一行表头，下面是数据行
- ⚠️ **列位置不固定**：旧表有首列空列，新表无空列。**按表头名称动态定位列**，不要写死索引
- 关键列名：货件单号 / 发货时间 / 仓库编码 / 货代/渠道 / 追踪单号
- 追踪单号列：一票可能挂多个单号（换行分隔），拆开处理，查第一个查不到自动换第二个
- **店铺提取**：从区块标题提取店铺名，有"店"字的取到店字为止（如"OD店"），无"店"字的按表格字段原样填（如"AI眼镜""QM发货号""NozlaID""ID发货号"）

## 脚本结构（/root/tracking/ 下）

| 脚本 | 作用 |
|---|---|
| `tracking.py` | 核心：解析追踪表+货代表 → 双数据源合并 → 生成汇总表 xlsx（含店铺/船名/ETD/ETA/货代状态/备注列） |
| `weekly_report.py` | 日报包装：调 tracking.py 生成汇总表 + 压缩 zip + 输出摘要文本 |
| `monitor.py` | 变化检测监控（历史用途，现已合并进日报） |
| `state.json` | 状态缓存：已注册单号 carrier 映射 + last_summary 快照 |
| `追踪表.xlsx` | 用户追踪表（固定路径） |
| `货代表_*.xlsx` | 货代周报表（云驼等，可多张） |

## 执行流程

```bash
cd /root/tracking && python3 weekly_report.py
```

输出：摘要文本（总票数/签收/在途/异常/查不到）+ zip 文件 /root/物流追踪汇总.zip

## 汇总表列（共 16 列）

货件单号 | 店铺 | 发货时间 | 运输方式 | 渠道 | 目的仓 | 追踪单号 | 承运商 | 当前状态(带色) | 最新节点 | 最新时间 | 船名 | 开船日 | 预计到港 | 货代状态 | 备注

## 已验证结论（2026-08 实测）

- ✅ UPS/DPD/FedEx 单号（`1Z...`/`1ZC...`/`155...`/`1ZK...`/`876...`）能查
- ❌ **云驼卡派**（`999...`）→ 17TRACK 识别不了（但货代表能补上）
- ❌ **清速达纯数字**（`8736...`）→ 识别不了
- ❌ **信易通卡派**（`XYT...`）→ 识别不了（小货代无周报表，暂无法查）
- ❌ **信易通德国**（`ZK...`）→ 识别不了（同票第2单号 `1ZK...` 能查）
- ✅ **四季国际**（德国空派，`1ZB...` UPS）→ 能查
- 货代表实测：云驼 6 票 `999...` 补上船名 MATSON WAIKIKI、开船 8/26、预计到港 9/6

## 踩坑记录（务必遵守）

1. 17TRACK 网页版 `.net` 被 Cloudflare 反爬拦截（403），**必须走 API**（api.17track.net 不受拦截）
2. register 后需等待 5 秒再 gettrackinfo（异步抓取），否则新单号返回"No tracking information"
3. `latest_event` 可能为 null，取值前必须 `ti.get("latest_event") or {}`
4. Discord 发 .xlsx 用户收不到，必须打包 zip
5. "递延"是英国 VAT 税务递延，不是运输方式，不能当空运关键词
6. 货代表匹配键是「运单号」=「追踪单号」，不是 FBA 号
7. 服务器是 UTC 时区，cron 表达式要换算（北京时间 9:20 = UTC 1:20 = `20 1 * * *`）
